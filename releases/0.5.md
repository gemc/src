# GEMC Release 0.5

This version includes:

- Mixed native and CAD geometry in one database-backed system.

<br/>

# Release notes

- SQLite and ASCII systems can contain native and CAD volumes together, removing the need for a separate
  CAD `gsystem` entry.
- The related `pygemc` CAD authoring change is documented in the
  [pygemc release notes](https://github.com/gemc/pygemc/blob/main/releases/v0.5.0.md).

<br/>

## Detailed list of changes and fixes

- True-information records now include `nphotons`, the number of unique optical-photon tracks in each hit,
  so the GUI Analyzer can display photon counts for detectors such as LTCC. Optical-photon hits are drawn as
  small green markers even when Geant4 assigns a terminal energy deposit to the photon.
- Automatic Analyzer Y-axis limits now round the highest bin count up to a clean decimal boundary, such as
  2 for one entry or 110 for 105 entries, instead of applying a fractional 15 percent margin.
- Digitization plugins can request post-hit track termination. The sensitive detector applies `fStopAndKill`
  only after all touchables have stored the current step, allowing terminal optical detectors to prevent
  trapped photons without adding geometry that can obscure the sensitive volume.
- The Volumes tab now shows a mirror button for volumes with an optical surface. The button opens a closable
  window containing the complete mirror definition.
- Geant4 object-factory selection now happens per volume: a `solid = CAD` row uses the CAD mesh builder
  while native rows in the same system keep the native builder. Relative SQLite mesh paths resolve from
  both an asset root and its `<system>/` subdirectory, supporting combined experiment layouts such as
  `ltcc/stls` without changing the stored `parameters = "stls/<mesh>, <scale>"`. The `description`
  column remains available for descriptive text. Existing rows with the path in `description` remain
  supported. SQLite database filenames also resolve relative to the steering-card directory.
