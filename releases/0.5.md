# GEMC Release 0.5

This version includes:

- Mixed native and CAD geometry in one database-backed system.
- Typed absence and required values throughout the configuration schema.
- Typed optional metadata inside loaded geometry volumes.
- Coherent, sentinel-free calculated state for detector hits.
- Typed translation-table entries and scoped compile-time constants without placeholder macro state.

<br/>

# Release notes

- SQLite and ASCII systems can contain native and CAD volumes together, removing the need for a separate
  CAD `gsystem` entry.
- Optional scalar settings now use typed `std::optional` values, while required schema entries are represented
  explicitly instead of by string or numeric sentinels.
- Geometry loading now converts empty and legacy unset spellings to `std::nullopt` once, so downstream field,
  digitization, copy, boolean-solid, mirror, annotation, and imported-parameter code no longer interprets
  serialized sentinel strings.
- `GHit` now calculates and invalidates all derived values as one state, preventing partially calculated or
  stale energy, time, position, process, and mother-track metadata.
- Translation-table lookup remains fail-fast, but successful lookup now exposes the stored electronics entry
  directly and insertion no longer depends on a sentinel-filled default object.
- First-party defaults, labels, error codes, and serialized sentinels now use typed `inline constexpr`
  constants in their owning module namespaces instead of unscoped preprocessor definitions.
- The matching `pygemc` geometry serialization and CAD authoring changes are documented in the
  [pygemc release notes](https://github.com/gemc/pygemc/blob/main/releases/v0.5.0.md).

## Compatibility notes

- The C++ `GOptions::getScalarString()`, `getScalarInt()`, and `getScalarDouble()` APIs have been removed.
  Callers must use the corresponding `getRequiredScalar*()` or `getOptionalScalar*()` accessor.
- Optional `GVolume` metadata getters now return `const std::optional<std::string>&`. This affects
  `getEMField()`, `getDigitization()`, `getGIdentity()`, `getCopyOf()`, `getSolidsOpr()`, `getMirror()`, and
  `getImportedFile()`. The ASCII `NULL` token and SQLite `NULL` representation remain unchanged.
- `GHit::calculateInfos()`, `GHit::getProcID()`, and the misspelled `GHit::getAvgGlobaPosition()` have been
  removed. Derived getters calculate the complete state lazily; use `getAvgGlobalPosition()` for the corrected
  spelling. `getProcessName()` now returns `const std::optional<std::string>&`. The parallel mother-track
  getters have been replaced by `getMotherInfos()` and `getMotherInfo()`, whose PID and vertex members are
  optional.
- `GTouchable::getStepTimeAtElectronicsIndex()` now returns `const std::optional<int>&`, and
  `GDigitizedData::getTimeAtElectronics()` returns `std::optional<int>`.
- `GSystem::getAnnotations()` and `GVolume::getParameters()` now return optional strings. Missing native-solid
  parameters are rejected when the solid is built; CAD volumes retain the legacy description fallback.
- `GModifier` shift and tilt values and the `useBackupMaterial` option are optional. `GVolume::getShift()` and
  `getTilt()` now return optional strings, and configured tilt modifiers are applied during rotation building.
- `GElectronic` is no longer default-constructible, and its constructor now takes
  `GElectronic::ComparisonMode` instead of an integer. For a full-address comparison, replace mode `2` with
  `GElectronic::ComparisonMode::crate_slot_channel`; modes `0` and `1` become `crate` and `crate_slot`.
  `GTranslationTable::getElectronics()` now returns `const GElectronic&` rather than a copy. Constructors and
  setters reject negative crate, slot, or channel values.
- `GVariable` schemas use typed YAML defaults. Use `goptions::REQUIRED` for required entries and
  `std::nullopt` for optional entries; optional numeric values are available through
  `getOptionalScalarInt()` and `getOptionalScalarDouble()`.
- Particle momentum is required. A particle entry without `p` is now a configuration error rather than a
  particle with a sentinel momentum. An omitted random seed still selects an automatically generated seed,
  while every explicitly supplied integer is treated as the requested seed.
- `searchForDirInLocations()` returns `std::optional<std::filesystem::path>`; absence is no longer encoded as
  a string path.
- `GAnalysisAccumulator::currentRunNumber()` returns `std::optional<int>`. Premature access to resolved
  `GVolume` names, Analyzer run numbers, or the EventDispenser beam-on timestamp now reports a contextual
  lifecycle error.
- C++ convention constants now require their owning namespace, such as
  `gfields::ERR_WRONG_FIELD_NOT_FOUND` and `gtranslationTable::EC__TTNOTFOUNDINTT`. The remaining serialized
  null marker is internal to format-boundary code. Unscoped macro aliases are not provided.

## Detailed list of changes and fixes

- The GEMC startup banner now reports the Geant4 installation prefix resolved from `geant4-config`, helping
  diagnose missing or mismatched Geant4 runtime environments.
- True-information records now include `nphotons`, the number of unique optical-photon tracks in each hit,
  so the GUI Analyzer can display photon counts for detectors such as LTCC. Optical-photon hits are drawn as
  small green markers even when Geant4 assigns a terminal energy deposit to the photon.
- Automatic Analyzer Y-axis limits now round the highest bin count up to a clean decimal boundary, such as
  2 for one entry or 110 for 105 entries, instead of applying a fractional 15 percent margin.
- Digitization plugins can request post-hit track termination. The sensitive detector applies `fStopAndKill`
  only after all touchables have stored the current step, allowing terminal optical detectors to prevent
  trapped photons without adding geometry that can obscure the sensitive volume.
- The Volumes tab now shows a mirror button for volumes with an optical surface. The button opens a closable
  window containing the complete mirror definition.
- Geant4 object-factory selection now happens per volume: a `solid = CAD` row uses the CAD mesh builder
  while native rows in the same system keep the native builder. Relative SQLite mesh paths resolve from
  both an asset root and its `<system>/` subdirectory, supporting combined experiment layouts such as
  `ltcc/stls` without changing the stored `parameters = "stls/<mesh>, <scale>"`. The `description`
  column remains available for descriptive text. Existing rows with the path in `description` remain
  supported. SQLite database filenames also resolve relative to the steering-card directory.
- Sensitive CAD volumes now omit native-solid dimension metadata, avoiding numeric parsing of the encoded
  mesh path and scale when their digitization touchables are registered.
- Translation-table insertion now uses `try_emplace()`, so duplicate keys preserve their existing entries
  without requiring a default-constructible `GElectronic` mapped type.
- Removed the unused `GOptions::option_verbosity_name` member and the obsolete post-lookup hardware-address
  sentinel check.
- Scene-text depth, display angles, random seeds, geometry annotations and parameters, hit mother metadata,
  touchable electronics indices, and digitized electronics times now model absence with `std::optional`.
- Geometry modifiers, backup materials, run-context state, Analyzer run state, and ASCII field-map axis lookup
  now use typed optional values instead of module-specific strings or `-1`.
- Added 225 typed `inline constexpr` constants in place of first-party value and formatting macros. Feature
  switches, call-site function-name expansion, Doxygen guards, and CADMesh lexer macros remain macros because
  their behavior depends on preprocessing.
- Documented converted progress-bar and translation-table constants as C++ variables so Doxygen no longer
  interprets them as removed preprocessor definitions, and corrected the SQLite factory's lifecycle reference.
- Updated the generated-documentation link checker for Doxygen 1.18's obfuscated external email links.
